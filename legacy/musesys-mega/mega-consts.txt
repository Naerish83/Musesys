MuseSys Mega Plugin Architecture Audit & Expose
Hey Boss. I took a deep dive into the musesys-mega directory to map out the entire vibe. Here is the master list of all the custom data structures, touchpoints, and little details keeping the rug tied together. We've got flags for the inconsistencies in Work Order metadata as well, so we can get this refactored and chill.

🚨 Work Order Metadata Inconsistencies & Flags
Dude, the work order naming is a bit un-chill right now. There are several meta keys floating around that seem to serve similar or identical functional purposes across different modules.

Global/Order-level Work Orders:
_muse_global_work_order (in muse-checkout-orchestrator)
_work_orders (array/consolidated, used in muse-product-request, muse-wo-consolidation, musesys-account-dashboard)
_primary_work_order (in musesys-account-dashboard)
_muse_workorder (defined in musesys-workorder-column)
Line-item Work Orders:
_muse_lineitem_workorder (in musesys-workorder-column)
Other overlapping structures:
Tracking Numbers: _tracking_number (product requests) vs _muse_latest_tracking_number (partial ship).
Install Stores: _install_stores vs _musesys_install_store vs _muse_global_install_store.
